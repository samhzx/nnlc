NNLC GUI 详细使用说明

从准备 rlog、选择参数，到训练完成、检查模型与排查错误。本说明与当前项目中的 nnlc_gui.py 行为保持一致。

适用：NNLC_Trainer one-dir 版本 训练设备：Windows x64 训练后端：CPU 更新日期：2026-09-07

1. 下载、解压与启动

  1. 下载构建产物在 GitHub Actions 对应的成功构建中，下载 NNLC_Trainer-windows-x64-onedir-7z。构建产物保留 14 天，请及时下载。
  2. 完成两层解压GitHub 通常先下载一个 ZIP 包；先解开外层 ZIP，得到 NNLC_Trainer-windows-x64-onedir.7z，再使用 7-Zip 或 WinRAR 解开内层 7z。不要直接在压缩软件预览窗口中运行程序。
  3. 保留整个目录进入解压后的 NNLC_Trainer 文件夹，确认其中同时存在 NNLC_Trainer.exe 和 _internal 文件夹。
  4. 启动 GUI双击 NNLC_Trainer.exe。程序是 one-dir 形式，目标电脑无需另外安装 Python、Julia 或项目依赖。
不能只复制 EXE。Julia、Python 包、训练脚本和运行库位于同目录的 _internal 中。只拿走 NNLC_Trainer.exe 会导致程序启动或训练失败。
Windows 安全提示：如果系统提示“未知发布者”，请先确认压缩包来自你自己的 GitHub Actions 构建，再选择“更多信息”并运行。不要运行来源不明的程序包。

2. 训练前准备

rlog 数据

输入目录可以包含多层路线和分段子目录。程序会递归查找文件名完全匹配 rlog、rlog.zst 或 rlog.bz2 的文件。

可用磁盘

输出目录会产生多个大型 CSV。超大数据使用流式模式时建议至少预留 100 GB；程序会在启动流程时报告剩余空间并给出警告。

稳定供电

训练可能持续较长时间。关闭 Windows 睡眠，保持窗口打开，并避免在训练期间移动程序目录、输入目录或输出目录。

数据质量

建议使用 20 至 30 条不同路线、约 5 至 10 小时的干净数据，覆盖城市、郊区、高速、左右弯和坡度变化。

推荐的目录结构

D:\reallog\
├─ 2026-08-30--10-15-00\
│  ├─ 0\rlog.zst
│  ├─ 1\rlog.zst
│  └─ 2\rlog.zst
└─ 2026-08-31--16-40-00\
   ├─ 0\rlog.zst
   └─ 1\rlog.zst
可以直接选择上层目录。选择示例中的 D:\reallog 即可，不需要逐个选择路线或分段。

4. 每个参数怎样填写

编号与字段作用与填写方法默认行为是否记忆
1. reallog 目录选择包含 rlog 的上层目录。程序递归查找 rlog、rlog.zst、rlog.bz2。空白，必须选择存在的目录。不记忆
2. 输出目录保存中间数据、图片、训练结果和最终车型 JSON。可以输入路径，也可以点击“浏览...”。优先使用 %USERPROFILE%\Documents\NNLC_Output；Documents 目录不存在时使用程序当前目录下的 NNLC_Output。不记忆
3. 车型最终模型文件名使用这里的文本。通常填写车辆 carFingerprint，例如 BYD_TANG_DMI_24。程序只检查非空，不限制格式。首次为 BYD_TANG_DMI_24，以后回填上次内容。会记忆
4. 路线阈值勾选自动推荐时不需要填写。手动设置必须是 0-100 的整数；越高越严格，保留路线越少。自动推荐，根据高质量路线比例选择 70、60 或 40。不记忆
生成覆盖度图生成 coverage.png，用于检查车速、横向加速度和接管等覆盖情况。建议保持勾选。已勾选不记忆
5. 训练模式在 CPU 标准模式和 CPU 流式低内存模式之间选择。选择方法见下一节。首次为 CPU 标准模式。会记忆
6. 日志处理模式容错模式会跳过无法读取的 rlog 并打印清单；严格模式遇到第一个损坏文件就停止。容错模式会记忆
7. 保留完整中间 CSV只在流式模式中可修改。取消后，仅当整个训练和质量验证成功时才删除大型中间 CSV；失败时仍保留现场文件。已勾选会记忆
8. 开始训练先校验目录、车型、阈值和模式，再启动后台训练。训练期间参数与按钮会被锁定。点击后清空旧的界面日志。不适用
9. 打开输出目录在 Windows 文件资源管理器中打开当前输出目录。目录尚未创建时会提示先完成一次训练。训练期间不可用。不适用
10. 运行日志显示命令、步骤、行数、警告、Julia 输出、模型验证结果和最终路径。报错时应保留或复制完整日志。自动滚动到底部。不保存到文件

5. 训练模式与日志模式选择

CPU 标准模式与流式模式

项目CPU 标准模式CPU 流式低内存模式
适合场景数据量较小、内存充足，优先追求处理速度。超大数据、上亿行 CSV 或约 16 GB 内存电脑。
单个 rlog逐个文件完整读取，并按 logMonoTime 稳定排序。同样逐个文件完整读取并排序，不设置固定排序窗口。
后续 CSV 处理部分步骤会完整载入数据。评分、剪枝、覆盖度、验证抽样和 Julia 预处理采用分块或流式处理。
Julia batch size163844096
速度通常更快。需要多遍顺序扫描，通常更慢。
训练规则两者都使用 CPU，并保持相同的 18 维输入、路线隔离、对称增强、损失规则及模型结构。模式不是“质量高低”选项。

普通数据推荐

CPU 标准模式

数据能轻松放入内存，或已有经验表明训练不会造成系统换页时使用。

低内存/超大数据推荐

CPU 流式低内存模式

16 GB 内存、数千万至上亿行、标准模式内存不足时使用，同时确保输出磁盘空间充足。

容错模式与严格模式

模式损坏或未写完整的 rlog适用情况
容错模式（默认）记录路径和原因，跳过该文件，继续处理剩余日志。原生解析进程崩溃时会先在全新进程中重试一次。日志从设备下载时可能仍在写入，或数据来源较多时。
严格模式显示导致失败的完整 rlog 路径和退出码后立即停止，保留旧输出，不用部分文件覆盖已有有效 CSV。要求每一个日志都必须完整，希望尽早发现采集或传输问题时。
容错不等于忽略数据质量。训练结束前应查看日志中的跳过清单。如果大量 rlog 被跳过，剩余样本可能不足或覆盖不完整，应重新下载对应日志后再训练。

6. 开始训练与运行期间操作

  1. 确认输入目录目录必须存在，并且内部至少包含一个受支持的 rlog 文件。
  2. 确认输出空间不要把超大任务输出到剩余空间不足的系统盘。输出目录不存在时程序会自动创建。
  3. 检查车型与阈值车型不能为空。首次训练建议保留“自动推荐”，避免阈值过高把数据全部删除。
  4. 选择模式按内存和数据规模选择标准或流式；不确定且电脑只有 16 GB 内存时优先流式。
  5. 点击开始训练运行日志会先显示“训练任务已启动”，状态栏变为“训练中，请保持窗口打开...”。
  6. 观察日志进度条表示任务仍在运行，不表示准确百分比；右侧计时显示已运行时间。
  7. 等待完成提示成功时状态栏显示“训练完成”，弹窗给出最终模型路径；失败时弹窗显示异常原因。
首次 Julia 训练可能 3 至 10 分钟没有新输出。这是 Julia 编译依赖的正常现象。只要程序未弹出失败、系统仍有 CPU 或磁盘活动，就先继续等待。
不要直接强制关闭。训练中点击窗口关闭按钮会询问是否中断。确认退出后，GUI 会结束当前 Python/Julia 子进程树；未完成的模型不会部署。

日志颜色含义

蓝色：普通信息、路径和模式
绿色：步骤成功、验证通过
橙色：警告，任务可能仍会继续
红色：错误、质量验证失败
紫色：标题和阶段总结
青色：当前流程步骤

7. 程序内部的训练流程

生成覆盖度图时共有 8 步；取消该选项时跳过第 5 步，界面显示 7 步。

  1. 提取横向控制数据递归读取 rlog，单个文件完整按时间排序，生成带时序特征的 lateral_data.csv。
  2. 评估路线质量根据激活时长、饱和、停车、变道等指标评分，并计算自动推荐阈值。
  3. 修剪低质量路线删除低于阈值的路线，生成 routes_pruned.csv。
  4. 移除干预帧识别驾驶员修正与机械干扰，生成最终训练数据 interventions_pruned.csv。
  5. 生成覆盖度图（可选）输出 coverage.png，用于判断训练数据覆盖是否均衡。
  6. Julia CPU 训练为当前车型准备训练输入，执行 latmodel_temporal.jl 并输出模型 JSON 和训练图。
  7. 验证模型质量校验 JSON 字段、18 维输入、权重、归一化参数和测试损失，并尝试生成两张模型验证图。
  8. 部署到输出目录将验证通过的模型原子复制为输出目录根部的 车型.json。已有同名模型会先备份为 车型.json.bak。
只有质量验证通过才会部署。训练脚本生成 JSON 不代表流程已经成功；必须看到 GUI 的“训练完成”弹窗和绿色“模型质量验证通过”。

8. 输出目录和文件用途

NNLC_Output\
├─ lateral_data.csv                    # rlog 提取后的完整数据
├─ routes_pruned.csv                   # 路线阈值筛选后数据
├─ interventions_pruned.csv            # 移除干预后的最终训练数据
├─ coverage.png                        # 数据覆盖度图（勾选时生成）
├─ 车型.json                            # 最终可部署模型，最重要的文件
├─ 车型.json.bak                        # 重训覆盖前的旧模型备份（如有）
├─ validation\
│  ├─ lat_accel_vs_torque.png          # 横向加速度与扭矩验证图
│  └─ torque_vs_speed.png              # 扭矩与车速验证图
└─ training_input\
   ├─ 车型.csv                          # 交给 Julia 的训练输入
   └─ training_results\车型\
      ├─ 车型.json                      # Julia 原始模型结果
      ├─ 车型.training.png              # 训练过程图
      ├─ 车型-a.png / 车型-a.pdf        # Julia 分析图
      └─ 车型-b.png / 车型-b.pdf        # Julia 分析图
最终交付文件：通常使用输出目录根部的 车型.json。它是在质量验证通过后部署的副本，不要误用失败任务留下的中间文件。

关闭“保留完整中间 CSV”之后

该选项只对流式模式生效。整个训练、质量验证和部署均成功后，程序尝试删除：

  • lateral_data.csv
  • routes_pruned.csv
  • interventions_pruned.csv
  • training_input\车型.csv

模型、统计图片和训练结果目录会保留。任务失败或取消时不会执行成功后的清理，以便排查。

复用同一个输出目录时要注意：新训练开始前会清理 training_input 根目录中旧的 CSV，并删除同车型旧的 training_results\车型 结果目录；输出目录根部的同名模型会保留一份 .bak 备份。

9. 怎样判断数据和模型是否合格

检查点程序判断建议处理
提取数据量少于 10,000 行会警告。继续训练前优先补充更多有效驾驶数据。
路线修剪结果0 行直接失败；少于 5,000 行严重不足；少于 20,000 行提示可能过拟合。降低路线阈值，检查激活驾驶数据，或补采路线。
干预移除结果0 行直接失败。检查数据是否大多为人工接管、变道、颠簸或无效控制状态。
模型结构必须包含完整字段、18 个指定输入、正确权重维度和激活函数。不要手工修改 Julia 生成的 JSON；结构错误需重新训练。
测试损失0 ≤ model_test_loss < 0.05 才通过。未通过时补充更均衡、更干净的数据，再调整阈值重训。
验证图图表生成失败只会警告，不改变已经完成的数值质量判定。模型可以通过结构与损失验证，但仍建议解决绘图错误后人工查看曲线。

覆盖度图重点看什么

  • 城市、郊区、高速车速区间是否都有足够样本。
  • 左转与右转、正负横向加速度是否明显偏向一侧。
  • 低速急弯、高速缓弯等边界区域是否为空。
  • 接管比例是否过高，是否存在大量饱和或无效路线。

10. 上次设置保存在哪里

在 Windows 中，GUI 把用户偏好写入：

%APPDATA%\NNLC\settings.json

保存内容只有：

  • 上次填写的车型
  • 上次选择的训练模式
  • 上次选择的日志处理模式
  • 是否保留完整中间 CSV

输入目录、输出目录、手动阈值和“生成覆盖度图”不会保存。配置损坏或无法读取时，程序自动回退到默认设置；配置目录不可写不会阻止训练启动。

恢复默认偏好：先退出 GUI，再删除 %APPDATA%\NNLC\settings.json。下次启动时会重新创建。

11. 常见问题与排查顺序

提示“请选择有效的 reallog 目录”

当前填写的路径为空、目录不存在，或移动了原目录。重新点击“浏览...”选择实际存在的目录。路径使用 \ 或 / 不影响程序，GUI 会按 Windows 规则统一显示。

提示“数据目录中未找到 rlog 文件”

程序只识别文件名完全为 rlog、rlog.zst、rlog.bz2 的日志。rlog.tmp、rlog.part 或其他临时文件不会计入。检查下载是否完成，并确认选择的是包含这些文件的上层目录。

容错模式跳过了文件

常见原因是设备端日志仍在写入时就被下载、压缩流截断、传输不完整或 Cap'n Proto 数据损坏。记录日志中列出的文件路径，重新从设备下载；如果跳过比例很低且剩余数据充足，可以继续，但应检查覆盖度。

长时间停在 Julia 训练开始位置

首次运行会编译 Julia 依赖，约 3 至 10 分钟无输出可能正常。查看任务管理器中的 CPU、磁盘活动和可用内存。若最终出现非零退出码，保留从“命令:”开始到错误末尾的完整日志。

路线剪枝后没有剩余数据

手动阈值可能过高，或有效激活路线质量不足。先改回“自动推荐”；仍失败时降低阈值，并检查是否存在足够长的激活驾驶、过多停车、变道、饱和或接管。

标准模式内存占用过高

切换到“CPU 流式低内存模式”。流式模式对大型 CSV 分块处理，内存不会随总行数线性增加，但会增加顺序扫描次数和总耗时。输出磁盘需预留足够空间。

模型质量验证未通过

程序不会把该模型部署为最终模型。查看日志中列出的 JSON 结构问题或 model_test_loss。不要仅通过反复提高或降低阈值碰运气，应结合 coverage.png 补齐缺失工况并减少污染数据。

验证图生成失败，但日志显示质量判定通过

模型结构与测试损失验证在前，绘图在后。两张验证图生成失败会显示警告，但不会把已通过的数值质量判定改为失败。仍建议保留日志并修复绘图问题，以便人工检查模型曲线。

双击 EXE 后缺少模块、Julia 或 DLL

通常是只复制了 EXE、压缩包没有完整解压，或安全软件隔离了 _internal 文件。重新完整解压整个 NNLC_Trainer 文件夹，并确认 _internal\julia-runtime\bin\julia.exe 存在。

输出目录空间不足

停止后把输出目录改到容量更大的磁盘。不要在训练中移动或删除正在增长的 CSV。流式模式关闭“保留完整中间 CSV”只能在整个任务成功后清理文件，不能降低训练过程中的磁盘峰值。

怎样提供一份可分析的错误日志

不要只截取最后一行。应包含：GUI 选择的模式、阈值、从失败步骤标题开始的全部内容、执行命令、Traceback 或 Julia 错误、退出码，以及被跳过的 rlog 清单。路径中的个人用户名可以打码，但应保留目录层级和文件名。

12. 训练完成后的检查清单

  1. 确认 GUI 明确显示“训练完成”不能只依据 Julia 输出了 JSON 判断完成。
  2. 确认质量验证通过日志应显示 JSON 结构正确、测试损失小于 0.05。
  3. 确认最终模型位置输出目录根部应存在与车型名称一致的 车型.json。
  4. 检查跳过日志清单使用容错模式时，确认被跳过的数量不会显著破坏数据覆盖。
  5. 检查覆盖度与验证图打开 coverage.png 和 validation 中的两张曲线图，确认没有明显空白或异常形状。
  6. 保留可回退文件首次上车验证前备份旧模型和本次训练日志；同名旧模型通常位于 车型.json.bak。
道路验证注意安全。新模型应先在可控环境中低风险验证，并随时准备接管。离线质量验证通过不等于覆盖了所有车辆状态和道路工况。
