NNLC GUI 详细使用说明

从准备 rlog、选择参数，到训练完成、检查模型与排查错误。本说明与当前项目中的 nnlc_gui.py 行为保持一致。

适用：NNLC_Trainer 独立 EXE + 可复用 Julia 环境 训练设备：Windows x64 训练后端：CPU 更新日期：2026-09-15

1. 下载、解压与启动

  1. 下载程序在 GitHub Actions 对应的成功构建中下载 NNLC_Trainer-windows-x64-exe 或版本化发布包。解开后得到 NNLC_Trainer.exe，也可以把 NNLC_Trainer-<version>-windows-x64.exe 重命名为 NNLC_Trainer.exe 后使用。
  2. 首次下载环境从 julia-runtime-v1 GitHub Release 下载 NNLC_Julia_Runtime-windows-x64-v1.zip，不要手工解开这个环境 ZIP。
  3. 放在同一目录确认 NNLC_Trainer.exe 与环境 ZIP 位于同一个普通可写目录，不要直接在压缩软件预览窗口中运行程序。
  4. 启动 GUI双击 NNLC_Trainer.exe。首次启动会自动验证并解压为 NNLC_Runtime，目标电脑无需另外安装 Python、Julia 或项目依赖。
后续只更新 EXE。首次成功生成 NNLC_Runtime 后，可以删除环境 ZIP。打包后的程序启动时会静默检查一次更新；发现新版本后会把带版本号的新 EXE 下载到当前程序目录，不会覆盖正在运行的文件。关闭当前程序后再运行新 EXE，原来的 NNLC_Runtime 可以继续使用。如果 Julia 环境发生变化，需要手动下载新的 EXE 和 Runtime ZIP。
不要只复制半个运行环境。NNLC_Runtime 必须同时包含环境清单、julia-runtime 和 julia-depot。环境缺失、损坏或版本不匹配时，请重新下载完整 ZIP。
Windows 安全提示：如果系统提示“未知发布者”，请先确认 EXE 和环境 ZIP 来自本仓库的 GitHub Actions 或 Release，再选择“更多信息”并运行。不要运行来源不明的文件。

2. 训练前准备

rlog 数据

输入目录可以包含多层路线和分段子目录。程序会递归查找文件名完全匹配 rlog、rlog.zst 或 rlog.bz2 的文件。

可用磁盘

输出目录会产生多个大型 CSV。超大数据使用流式模式时建议至少预留 100 GB；程序会在启动流程时报告剩余空间并给出警告。

稳定供电

训练可能持续较长时间。关闭 Windows 睡眠，保持窗口打开，并避免在训练期间移动程序目录、输入目录或输出目录。

数据质量

建议使用 20 至 30 条不同路线、约 5 至 10 小时的干净数据，覆盖城市、郊区、高速、左右弯和坡度变化。

推荐的目录结构

D:\reallog\
├─ 2026-08-30--10-15-00\
│  ├─ 0\rlog.zst
│  ├─ 1\rlog.zst
│  └─ 2\rlog.zst
└─ 2026-08-31--16-40-00\
   ├─ 0\rlog.zst
   └─ 1\rlog.zst
可以直接选择上层目录。选择示例中的 D:\reallog 即可，不需要逐个选择路线或分段。

4. 每个参数怎样填写

2. 输出目录保存中间数据、图片、训练结果和最终车型 JSON。可以输入路径，也可以点击输入框右侧的 ··· 浏览按钮。首次优先使用 %USERPROFILE%\Documents\NNLC_Output；Documents 目录不存在时使用程序当前目录下的 NNLC_Output。以后回填上次路径。会记忆

6. 开始训练先校验目录、目标车型、阈值和模式，再启动后台训练。训练期间参数会被锁定，开始训练按钮不可点。点击后重置进度卡，并立刻创建本次日志文件。不适用
7. 打开输出目录在文件管理器中打开当前输出目录。目录尚未创建时会提示先完成一次训练。训练期间仍可打开。不适用

5. 训练模式与日志处理说明

标准模式与流式模式

项目标准模式流式模式

单个 rlog两种模式使用同一套提取器：默认 2 秒有界重排；若发现超出窗口的迟到事件，该 rlog 会丢弃候选结果并回退到全量稳定排序。

Julia batch size163844096

普通数据推荐

标准模式

数据能轻松放入内存，或已有经验表明训练不会造成系统换页时使用。

低内存/超大数据推荐

流式模式

6. 开始训练与运行期间操作

  1. 确认输入目录目录必须存在，并且内部至少包含一个受支持的 rlog 文件。
  2. 确认输出空间不要把超大任务输出到剩余空间不足的系统盘。输出目录不存在时程序会自动创建。
  3. 检查目标车型与阈值目标车型不能为空。首次训练建议保留“自动推荐”，避免阈值过高把数据全部删除。
  4. 选择训练模式按内存和数据规模选择标准或流式；不确定且电脑只有 16 GB 内存时优先流式。rlog 提取默认自动使用多个 worker 并行解析。
  5. 点击开始训练进度卡先显示“训练任务已启动”，状态栏变为“训练中，请保持窗口打开...”。同时在程序运行目录创建独立日志 logs/YYYYMMDD_HHMMSS_车型.log；同秒冲突时自动追加编号。
  6. 观察进度进度条按 7 个流水线步骤前进，卡片只显示最新一行日志；耗时会持续更新，但不代表 Julia epoch 百分比。完整日志请点“打开日志”。
  7. 等待完成提示成功时状态栏显示“训练完成”，弹窗给出最终模型路径；失败时弹窗显示异常原因。
Julia 训练前半段可能暂时没有新输出。这不一定是在重新编译依赖。进度卡和完整日志会先提示“Julia 正在启动”，随后区分“加载已缓存依赖”“读取训练数据”和“编译训练代码（仅本次进程）”。该环境第一次训练才会编译依赖并写入缓存，可能需要几分钟；之后同一 NNLC_Runtime 会加载缓存，不必每次重编依赖。若暂时没有新输出，日志大约每 30 秒按当前阶段重复提示。只要程序未弹出失败、系统仍有 CPU 或磁盘活动，就先继续等待。进入训练循环后，完整日志会每轮追加 Training progress: epoch/epoch_max，但窗口总进度仍停在第 5/7 步，直到验证开始。Windows GUI 启动 Julia 时不再弹出黑色控制台。
rlog 并行提示：命令行默认自动选择并行度，`--rlog-workers 1` 可恢复串行模式。SSD 通常适合更高并行度，机械硬盘或低内存设备应降低 worker 数。超线程可能提升吞吐，但收益取决于解压、磁盘和物理核心数，建议通过实际基准测试选择。
不要直接强制关闭。训练中点击窗口关闭按钮会询问是否中断。确认退出后，GUI 会结束当前 Python/Julia 子进程树；未完成的模型不会部署。

完整日志写在哪里

完整训练日志不保存在输出目录，而是写入程序运行目录：

NNLC_Trainer.exe 所在目录\logs/YYYYMMDD_HHMMSS_车型.log

源码直接运行时，这个目录就是项目根目录下的 logs。窗口只显示最新一行；排查失败时请打开这份文件，而不是只看进度卡。

7. 程序内部的训练流程

GUI 默认执行完整的 7 步流程，并生成覆盖度图、提取 CSV 和最终训练 CSV。评分、路线剪枝和干预帧移除在一次合并扫描中完成，不再生成单独的 routes_pruned.csv。

  1. 提取横向控制数据递归读取 rlog，默认按 2 秒窗口重排事件；迟到事件超出窗口时该文件回退到全量稳定排序，生成带时序特征的 lateral_data.csv。较小的 zstd/bz2 日志在内存中解压，较大的仍写入临时文件。若 reallog 目录本身是 YYYYMMDD，或其直接子目录包含下载器那种日期目录，会先把各日结果写到 日期目录/lateral_data.csv；该文件已存在且表头正确时跳过该日，再按日期顺序合成输出目录的总表。补下载同一天的日志后，若要重新提取，需要手动删除该日的 lateral_data.csv。没有日期目录时仍只写输出目录，不会在数据目录生成 CSV。
  2. 评估路线质量根据激活时长、饱和、停车、变道等指标评分，并计算自动推荐阈值。
  3. 修剪路线并移除干预帧删除低于阈值的路线、饱和帧、变道帧和干预事件，直接生成最终训练数据 interventions_pruned.csv。
  4. 生成覆盖度图输出 coverage.png 和 coverage_gaps.txt。建议里的速度使用 km/h，并说明缺口该怎么补采。
  5. Julia CPU 训练为当前车型准备训练输入，执行 latmodel_temporal.jl 并输出模型 JSON 和训练图。
  6. 验证模型质量校验 JSON 字段、18 维输入、权重、归一化参数和测试损失，并尝试生成两张模型验证图。
  7. 部署到输出目录将验证通过的模型原子复制为输出目录根部的 车型.json。已有同名模型会先备份为 车型.json.bak。
只有质量验证通过才会部署。训练脚本生成 JSON 不代表流程已经成功；必须看到 GUI 的“训练完成”弹窗和绿色“模型质量验证通过”。

8. 输出目录和文件用途

NNLC_Output\
├─ lateral_data.csv                    # rlog 提取后的完整数据
├─ interventions_pruned.csv            # 移除干预后的最终训练数据
├─ coverage.png                        # 数据覆盖度图（始终生成）
├─ coverage_gaps.txt                   # 覆盖缺口补采建议，速度使用 km/h
├─ 车型.json                            # 最终可部署模型，最重要的文件
├─ 车型.json.bak                        # 重训覆盖前的旧模型备份（如有）
├─ validation\
│  ├─ lat_accel_vs_torque.png          # 横向加速度与扭矩验证图
│  └─ torque_vs_speed.png              # 扭矩与车速验证图
└─ training_input\
   ├─ 车型.csv                          # 交给 Julia 的训练输入
   └─ training_results\车型\
      ├─ 车型.json                      # Julia 原始模型结果
      ├─ 车型.training.png              # 训练过程图
      ├─ 车型-a.png / 车型-a.pdf        # Julia 分析图
      └─ 车型-b.png / 车型-b.pdf        # Julia 分析图
最终交付文件：通常使用输出目录根部的 车型.json。它是在质量验证通过后部署的副本，不要误用失败任务留下的中间文件。

GUI 始终保留中间 CSV

GUI 会保留提取 CSV 和最终训练 CSV，方便检查数据和排查失败原因。整个训练、质量验证和部署完成后，以下文件仍会保留：

  • lateral_data.csv
  • interventions_pruned.csv
  • training_input\车型.csv

如需在训练成功后清理这些文件，请使用命令行流程的 --no-keep-intermediates 参数；该参数不对应 GUI 控件。任务失败或取消时命令行也不会执行成功后的清理，以便排查。

复用同一个输出目录时要注意：新训练开始前会清理 training_input 根目录中旧的 CSV，并删除同车型旧的 training_results\车型 结果目录；输出目录根部的同名模型会保留一份 .bak 备份。

9. 怎样判断数据和模型是否合格

检查点程序判断建议处理
提取数据量少于 10,000 行会警告。继续训练前优先补充更多有效驾驶数据。
路线修剪结果0 行直接失败；少于 5,000 行严重不足；少于 20,000 行提示可能过拟合。降低路线阈值，检查激活驾驶数据，或补采路线。
干预移除结果0 行直接失败。检查数据是否大多为人工接管、变道、颠簸或无效控制状态。
模型结构必须包含完整字段、18 个指定输入、正确权重维度和激活函数。不要手工修改 Julia 生成的 JSON；结构错误需重新训练。
测试损失0 ≤ model_test_loss < 0.05 才通过。未通过时补充更均衡、更干净的数据，再调整阈值重训。
验证图图表生成失败只会警告，不改变已经完成的数值质量判定。模型可以通过结构与损失验证，但仍建议解决绘图错误后人工查看曲线。

覆盖度图重点看什么

  • 覆盖度建议不是弹窗，而是写在同目录的 coverage_gaps.txt，训练日志的可视化步骤里也会打印。
  • 热力图红色框表示该速度 × 横向加速度格子只有 1–49 个样本；完全空白的格子没有红框，常见于没跑过的高速区间。
  • 这里的“高速”按车速分箱判断，不是地图道路类型。没跑过 90 km/h 以上路段时，高速建议会写 0 样本。
  • 同时检查左右转向是否均衡，以及低速急弯、高速缓弯是否为空。
  • coverage_gaps.txt 会把缺口翻译成补采建议：目标速度用 km/h，并写明当前样本、为什么要补、怎么补和路线例子。

10. 上次设置保存在哪里

在 Windows 中，GUI 把用户偏好写入：

%APPDATA%\NNLC\settings.json

保存内容包括：

  • 上次选择的日志目录
  • 上次选择的输出目录
  • 上次填写的目标车型
  • 上次选择的训练模式

手动阈值和自动推荐开关不会保存。覆盖度图和中间 CSV 的保留行为固定，不需要保存设置。配置损坏或无法读取时，程序自动回退到默认设置；配置目录不可写不会阻止训练启动。已保存的目录下次会回填，即使当前不存在；开始训练时仍会检查日志目录是否有效。

恢复默认偏好：先退出 GUI，再删除 %APPDATA%\NNLC\settings.json。下次启动时会重新创建。

11. 常见问题与排查顺序

提示“请选择有效的日志目录”

当前填写的路径为空、目录不存在，或移动了原目录。重新点击输入框右侧的 ··· 浏览按钮选择实际存在的目录。路径使用 \ 或 / 不影响程序，GUI 会按 Windows 规则统一显示。

提示“数据目录中未找到 rlog 文件”

程序只识别文件名完全为 rlog、rlog.zst、rlog.bz2 的日志。rlog.tmp、rlog.part 或其他临时文件不会计入。检查下载是否完成，并确认选择的是包含这些文件的上层目录。

同一天补下载了 rlog，但训练数据没有增加

识别到 YYYYMMDD 日期目录时，每个日期目录里的 lateral_data.csv 是按天缓存。该文件已存在且表头与当前时序列一致时，即使后来又放入新 rlog 也不会重提。删除对应日期目录中的 lateral_data.csv 后再训练，该日才会重新提取并进入输出目录的总表。评分、剪枝和 Julia 训练仍针对合并后的总 CSV。

容错模式跳过了文件

常见原因是设备端日志仍在写入时就被下载、压缩流截断、传输不完整或 Cap'n Proto 数据损坏。记录日志中列出的文件路径，重新从设备下载；如果跳过比例很低且剩余数据充足，可以继续，但应检查覆盖度。

长时间停在 Julia 训练开始位置

先看最新一条阶段提示：启动、加载已缓存依赖、读取数据，或编译本次训练代码。该电脑上的第一次训练才需要编译依赖并写入缓存，可能要几分钟；之后同一环境主要是加载缓存、读 CSV，以及在本次进程中编译训练代码。查看任务管理器中的 CPU、磁盘活动和可用内存。若最终出现非零退出码，保留从“命令:”开始到错误末尾的完整日志。

路线剪枝后没有剩余数据

手动阈值可能过高，或有效激活路线质量不足。先改回“自动推荐”；仍失败时降低阈值，并检查是否存在足够长的激活驾驶、过多停车、变道、饱和或接管。

标准模式内存占用过高

切换到“流式模式”。流式模式对大型 CSV 分块处理，内存不会随总行数线性增加，但会增加顺序扫描次数和总耗时。评分、剪枝和干预处理已经合并为两遍扫描，不再单独写出 routes_pruned.csv。输出磁盘需预留足够空间。

模型质量验证未通过

程序不会把该模型部署为最终模型。查看日志中列出的 JSON 结构问题或 model_test_loss。不要仅通过反复提高或降低阈值碰运气，应结合 coverage.png 补齐缺失工况并减少污染数据。

验证图生成失败，但日志显示质量判定通过

模型结构与测试损失验证在前，绘图在后。两张验证图生成失败会显示警告，但不会把已通过的数值质量判定改为失败。仍建议保留日志并修复绘图问题，以便人工检查模型曲线。

提示发现新版本或下载更新失败

打包后的 Windows GUI 启动后会在后台检查一次更新。无更新或网络异常时不会弹窗。下载过程会显示进度，可以取消。失败、取消或校验失败时会删除未完成文件，正在运行的 EXE 不受影响。下载成功后关闭当前程序，运行同目录中带版本号的新 EXE 即可。

双击 EXE 后缺少模块、Julia 或 DLL

确认 NNLC_Runtime\runtime-manifest.json、NNLC_Runtime\julia-runtime\bin\julia.exe 和 NNLC_Runtime\julia-depot 同时存在。如果程序提示环境缺失、损坏或版本不匹配，将正确名称的环境 ZIP 放到 EXE 旁并重新启动；程序会先验证新环境，再自动替换旧目录，错误窗口也可直接打开下载页面。

Julia 环境解压时报 No such file or directory

这通常是旧版本的解压临时目录过长，触发了部分 Windows 电脑的路径限制。退出程序后删除 EXE 旁残留的 .NNLC_Runtime.extracting-* 临时目录，再把 EXE 和 ZIP 移到较短、可写的目录（例如 C:\NNLC）并使用新版程序重试。新版使用短临时目录；如果仍失败，请保留完整错误路径。

输出目录空间不足

停止后把输出目录改到容量更大的磁盘。不要在训练中移动或删除正在增长的 CSV。GUI 始终保留中间 CSV；命令行的 --no-keep-intermediates 只能在整个任务成功后清理文件，不能降低训练过程中的磁盘峰值。

怎样提供一份可分析的错误日志

不要只截取进度卡上的最新一行。请打开程序运行目录 logs 中对应的 YYYYMMDD_HHMMSS_车型.log，并包含：GUI 选择的模式、阈值、从失败步骤标题开始的全部内容、执行命令、Traceback 或 Julia 错误、退出码，以及被跳过的 rlog 清单。路径中的个人用户名可以打码，但应保留目录层级和文件名。

12. 训练完成后的检查清单

  1. 确认 GUI 明确显示“训练完成”不能只依据 Julia 输出了 JSON 判断完成。
  2. 确认质量验证通过日志应显示 JSON 结构正确、测试损失小于 0.05。
  3. 确认最终模型位置输出目录根部应存在与车型名称一致的 车型.json。
  4. 检查跳过日志清单确认被跳过的数量不会显著破坏数据覆盖。
  5. 检查覆盖度与验证图打开 coverage.png 和 validation 中的两张曲线图，确认没有明显空白或异常形状。
  6. 保留可回退文件首次上车验证前备份旧模型和本次训练日志。同名旧模型通常位于输出目录的 车型.json.bak；本次完整日志位于程序运行目录的 logs/YYYYMMDD_HHMMSS_车型.log。
道路验证注意安全。新模型应先在可控环境中低风险验证，并随时准备接管。离线质量验证通过不等于覆盖了所有车辆状态和道路工况。
