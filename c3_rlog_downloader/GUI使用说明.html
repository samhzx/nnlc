C3 rlog 下载器详细使用说明

从准备 SSH 私钥、连接 comma 设备，到下载 rlog.zst、确认设备清理和上传训练模型。本说明与当前项目中的 c3_rlog_downloader/gui.py 行为保持一致。

适用：C3_Rlog_Downloader 独立 EXE 设备：comma 3 / 3X，SSH 22 端口 用户：comma 程序版本：v1.2.2 更新日期：2026-10-21

1. 下载、解压与启动

  1. 下载程序在 GitHub Actions 对应的成功构建中下载 C3_Rlog_Downloader-windows-x64。解开后得到 C3_Rlog_Downloader.exe。
  2. 放到固定目录建议放到自己能记住的目录，例如 D:\C3_Rlog_Downloader\。不要放在会自动清理的临时目录。
  3. 准备 SSH 私钥使用能登录设备的私钥文件。程序只读取你选择的本机路径，不会把私钥内容写入设置文件。
  4. 启动 GUI双击 C3_Rlog_Downloader.exe。目标电脑无需另外安装 Python、Paramiko 或项目依赖。
这是独立程序。下载器不依赖 NNLC 训练器、Julia 环境或 Python 源码目录。它可以单独使用，把 rlog 下载到本机后再交给训练器。
不要手工拼接运行目录。请使用 Actions 构建出的完整 EXE。源码构建时，在 Windows 上进入 c3_rlog_downloader 目录运行 build_windows.ps1，产物位于本目录 dist\C3_Rlog_Downloader.exe。

2. 使用前准备

设备网络

电脑和 C3 必须能互相访问。常见方式是设备连上同一局域网，或电脑连到设备热点。程序固定连接 SSH 22 端口，用户名为 comma。

SSH 私钥

需要一份能登录该设备的私钥。加密私钥会在连接时弹出输入口令；口令只用于本次解锁，不会保存。公钥必须已经放到设备的授权列表中。

本机磁盘

下载目录要有足够空间。程序只下载名称完全为 rlog.zst 的文件，但仍可能达到数 GB 到数十 GB。下载过程会先写 .part 临时文件，成功后再替换成正式文件。

设备端日志状态

正在写入的日志不要立刻下载。最近 5 分钟修改过的文件会被跳过，避免拷贝到半截压缩流。下载前尽量让车辆熄火、设备停止写入，或等该路线完成后再导。

推荐的目录结构

D:\C3_Rlog_Downloader\
├─ C3_Rlog_Downloader.exe
└─ C3_Rlogs\                      # 本机保存目录，可另外选择
    └─ 20261021\                  # 按电脑开始导出时的日期归档
        ├─ .c3_rlog_manifest.json  # 当天下载清单，用于断点续传
        └─ 000000a0--68a50e9c1b--2\
            └─ rlog.zst

4. 每个参数怎样填写

编号与字段作用与填写方法默认行为是否记忆
1. C3 IP 地址填写设备当前 IP，不要加 ssh:// 或端口。程序固定连接 22 端口。空白，必须填写。会记忆
2. 连接设备 / 断开连接IP 右侧按钮。未连接时显示“连接设备”；已连接后变成“断开连接”。连接中会显示“连接中...”。首次为未连接。不适用
3. SSH 私钥选择本机私钥文件。可直接输入路径，或点击右侧 ··· 浏览。空白，必须选择存在的文件。只记路径
4. 下载目录本机保存 rlog 的根目录。程序会在其中按当天日期再建一层目录。优先使用 %USERPROFILE%\Documents\C3_Rlogs。会记忆
5. 模型参数选择要覆盖上传到设备的训练结果 JSON。通常是训练器输出目录里的 车型.json。空白，不上传也能下载。会记忆
6. 上传把所选 JSON 覆盖上传到设备固定目录。必须先连接设备。未连接时不可用。不适用
7. 开始下载扫描设备 /data/media/0/realdata，下载稳定的 rlog.zst。下载期间按钮变成“取消”。必须先连接设备。不适用
8. 运行日志显示连接、扫描、跳过、失败、清理和上传结果。自动滚动到底部。不保存到文件

5. 连接设备

  1. 填写 C3 的 IP，选择 SSH 私钥，必要时再确认下载目录。
  2. 点击“连接设备”。状态点会变成“连接中...”。
  3. 如果私钥有口令，会弹出输入框。取消输入会中止本次连接，不会保存口令。
  4. 首次连接会自动接受并记录该 IP 的 SSH 主机指纹。
  5. 成功后状态点变为“已连接”，日志出现“设备已连接，可以开始下载”。
主机指纹变化会被拒绝。同一 IP 如果再次出现不同的 SSH 主机密钥，程序会报主机密钥不匹配并拒绝连接，避免连到被替换的设备。确认是自己重装或更换设备后，需要清理本机保存的指纹记录再连。
应用只记住这些内容：IP、私钥路径、本地下载目录、训练结果 JSON 路径。不保存私钥内容、口令或下载进度以外的设备密码。

6. 开始下载与运行期间操作

  1. 先连接未连接时不能下载或上传。
  2. 点击开始下载程序扫描 /data/media/0/realdata，只处理普通文件，不跟随符号链接。
  3. 只下载 rlog.zst文件名必须完全是 rlog.zst。摄像头视频、qlog 和其他日志都不会下载。
  4. 跳过近 5 分钟改过的文件这些文件视为仍在写入。日志会显示跳过数量。
  5. 按本机导出日期归档目录名是电脑开始导出时的 YYYYMMDD，不是路线目录日期，也不是远端文件修改日期。相对路径会保留，例如 20261021/000000a0--68a50e9c1b--2/rlog.zst。
  6. 观察进度进度区显示百分比、已传/总量、文件数、速度、剩余时间和当前文件。
  7. 需要停止时点取消按钮会变成“取消”。取消后不会清理设备文件。
支持续传。当天目录下的 .c3_rlog_manifest.json 会记录已成功发布的文件。已存在且大小、修改时间和设备标识匹配的文件会跳过。未完成的文件以 .part 保存，下次可继续。
两台设备不要下到同一个子路径。如果清单发现目标位置已经属于另一台设备的同名日志，会拒绝覆盖，避免把不同车的 rlog 混在一起。

下载结果怎么看

日志或状态含义下一步
下载完成：N 个新增，M 个已存在计划内的稳定 rlog 都已成功落到本机。会继续询问是否清理设备。
下载有失败项，设备日志未清理至少有一个 rlog 失败。程序不会清理设备。根据失败路径重新下载，不要此时清理设备。
没有可下载的稳定 rlog目录里没有完整的 rlog.zst，或文件都还太新。等路线写完后再试，或确认设备 realdata 目录是否有数据。
远端文件在扫描后发生变化扫描和下载之间文件又被改写。重新扫描下载，不要使用半截文件训练。

7. 设备清理

只有全部稳定 rlog 都下载成功后，才会弹出清理确认。清理不是自动执行。

清理范围大于本次下载。确认后会删除 realdata 中其他未下载的旧文件，包括摄像头和其他日志；随后删除因此变空的路线目录。最近 5 分钟有变化的文件会保留。此操作不可撤销。

确认框会显示大约会删除的文件数量和总大小。选择“否”则只保留本机文件，设备日志不动。选择“是”后，状态栏显示“正在清理 C3 日志”。

  • 清理前会再次核对文件大小和修改时间；已经变化的文件会跳过。
  • 不会跟随符号链接，也不会清理固定 realdata 目录以外的路径。
  • 空目录删除失败只会记录，不会把已经成功的下载视为失败。

8. 上传训练模型

下载器可以把 NNLC 训练得到的 JSON 覆盖上传到设备：

/data/openpilot/sunnypilot/neural_network_data/neural_network_lateral_control
  1. 先连接设备。
  2. 在“模型参数”中选择训练器输出的 车型.json。
  3. 点击“上传”。成功后会弹窗显示远端完整路径。
这是覆盖上传。同名文件会被直接替换。上传前确认 JSON 已经通过训练器质量验证，不要上传失败任务留下的中间文件。

9. 本机输出文件

下载目录\
└─ YYYYMMDD\
   ├─ .c3_rlog_manifest.json
   ├─ 路线目录\
   │  └─ rlog.zst
   └─ 路线目录\rlog.zst.part          # 仅未完成时存在
文件用途
rlog.zst训练器实际读取的日志。把这一天的目录或更上层目录交给 NNLC 训练器即可。
.c3_rlog_manifest.json当天成功发布的文件清单，含设备标识、大小和修改时间，用于跳过已下载文件。
rlog.zst.part正在传输的临时文件。成功后会原子替换为 rlog.zst。
rlog.zst.part.json临时文件的元数据，传输成功后删除。
日期目录按电脑当天日期创建。不要按路线名里的日期理解归档位置。同一天多次下载会写入同一个 YYYYMMDD 目录并更新清单。

10. 上次设置保存在哪里

在 Windows 中，GUI 把用户偏好写入：

%APPDATA%\C3_Rlog_Downloader\settings.json

保存内容只有：

  • 上次填写的 C3 IP
  • 上次选择的 SSH 私钥路径
  • 上次选择的本地下载目录
  • 上次选择的模型 JSON 路径

不保存私钥内容、口令、主机指纹以外的敏感信息和下载日志。配置损坏或无法读取时，程序回退到空白 IP 和默认下载目录 文档\C3_Rlogs。

恢复默认偏好：先退出程序，再删除 %APPDATA%\C3_Rlog_Downloader\settings.json。下次启动会重新创建。

11. 常见问题与排查顺序

提示无法连接或超时

先确认电脑和设备在同一网络，IP 没有填错，设备 SSH 已开启。防火墙不要拦截 22 端口。可在命令行用同一私钥测试 ssh comma@设备IP。

私钥口令错误或取消输入

加密私钥必须输入正确口令。取消输入会中止连接，不会保存口令。如果反复失败，检查选中的是不是对应这台设备的那把钥匙。

主机密钥不匹配

同一 IP 的 SSH 指纹和本机记录不一致。可能是设备重装、更换，或网络中出现了另一台同 IP 设备。确认环境安全前不要继续。确认是自己的设备后，再清理本机记录的该 IP 指纹。

无法访问 realdata 目录

设备未完全启动、存储未挂载，或路径不存在。等设备进入可用状态后再连。程序只扫描 /data/media/0/realdata，不会改到其他目录下载。

下载失败且设备未被清理

这是保护行为。只要有一个稳定 rlog 失败，就不会询问清理。根据日志中的远端路径重试；磁盘满、中途断网、文件在扫描后变化都可能导致失败。

目标目录已有另一台设备的同名日志

请给每台车使用独立下载目录，或先把旧车数据移走。程序拒绝覆盖，是为了避免训练时混入其他车辆的 rlog。

清理后发现设备文件变少

如果当时点了确认，这是预期行为：未下载的旧摄像头和其他日志也会被删除。只有最近 5 分钟改过的文件会留下。以后若只想备份 rlog、不想清设备，下载完成后选择“否”。

上传模型后车上没有变化

确认上传的是训练器质量验证通过后的 车型.json，路径无误，并且设备上的 openpilot/sunnypilot 会读取该目录。上传成功只表示文件已覆盖到固定远端路径，不表示车辆已经加载新模型。

12. 下载完成后的检查清单

  1. 确认状态栏不是失败或取消成功下载后应看到下载完成，以及你选择的清理结果。
  2. 打开当天日期目录确认存在完整的 rlog.zst，而不是只留下 .part。
  3. 核对跳过数量如果跳过的近期文件很多，等车辆停稳后再补下一轮。
  4. 不要把半截日志拿去训练失败清单里的文件应重新下载。
  5. 需要清设备时再确认弹窗没把握就选“否”，先保留设备日志。
  6. 交给训练器时选对目录可以把某一天的目录，或包含多天日期目录的上层目录，作为 NNLC 训练器的 reallog 目录。
下一步：使用 NNLC 训练器读取这些 rlog.zst。下载器只负责把设备日志安全拷到电脑，不训练模型。
